## 一、产品定位

**一句话**：本地优先的桌面端语音助理——把你说的话，直接变成文字、编辑、或答案。

**核心价值**：
- 不只是"录音转文字"，而是"**语音驱动操作**"
- 强调**本地运行**（无需云端、数据不出机器）
- 面向需要高效输入的个人用户和会议记录场景

### 5.2 核心流程：流式转录

```
快捷键触发
    │
    ▼
采集 PCM 音频
    │
    ▼
WebSocket → /stream
    │
    ▼
Silero VAD 分段
    │
    ▼
ASR 引擎转写
    │
    ├──→ 说话人分群 (pyannote) → CAM++ 映射 → utterance 返回前端
    │
    └──→ 周期性摘要触发 → AI 生成摘要 → 推送前端
```

### 5.3 语音编辑流程（第二阶段）

```
快捷键触发（edit 模式）
    │
    ▼
读取当前应用选区（Ctrl+C 模拟）
    │
    ├─ 取不到选区 ──→ 提示用户 → 结束
    │
    ▼
采集语音 → ASR 转写 → 获得编辑指令
    │
    ▼
POST /process_text（selected_text + instruction）
    │
    ▼
写入剪贴板 → 模拟 Ctrl+V 回写
    │
    ├─ 回写失败 ──→ 提示用户手动粘贴
    │
    ▼
完成，显示成功提示
```

### 5.4 语音问答流程（第二阶段）

```
快捷键触发（ask 模式）
    │
    ▼
读取当前应用选区作为上下文
    │
    ├─ 无选区 ──→ 提示用户 → 结束
    │
    ▼
采集语音 → ASR 转写 → 获得问题
    │
    ▼
POST /process_text（selected_text + question）
    │
    ▼
弹出 Answer Panel 展示答案
    │
    ├──→ 复制答案
    └──→ 插入到当前应用
```

## 七、非功能需求

| 类别 | 要求 |
|------|------|
| 本地化 | 所有模型本地运行，无网络依赖 |
| 隐私 | 音频不上传，不留存 |
| 性能 | 流式转录首包延迟 < 2s |
| 稳定性 | 任一失败路径均有用户可见反馈，不静默失败 |
| 平台 | Windows 优先；macOS 第三阶段跟进 |
| 内存 | 默认引擎 < 4GB 显存，large 模型 ~6GB |
