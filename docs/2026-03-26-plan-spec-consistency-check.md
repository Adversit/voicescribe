## 3. 你强调的两个点，之前是怎么做的

### 3.1 模型只认 `models/`

你后来明确的口径是：

- 下载到项目根目录 `models/`
- 读取也只从项目根目录 `models/`
- 注册表旧路径统一 rebasing 到当前 `models/`

但在你明确之前，系统不是这样完全收死的。

之前的做法有 3 层偏差：

1. **配置层偏差**
   - 早期实现还保留了更通用的路径思路
   - 后端会结合 `VOICESCRIBE_MODEL_DIR`、`VOICESCRIBE_RUNTIME_DIR`、项目根目录来决定模型路径
   - 也就是说，系统当时不是“只认 `models/`”，而是“优先某些路径，再 fallback 到别的路径”

2. **桌面端启动层偏差**
   - Tauri 端启动后端时，曾把模型目录和运行时目录绑在一起
   - 结果是桌面端可能去读某个 runtime 目录下的 `models/`
   - 这就导致你明明项目根目录已经有模型，但前端仍显示未下载

3. **注册表路径偏差**
   - `models/voicescribe_models.json` 里还存在历史旧绝对路径
   - 即使当前项目根目录已经有模型，只要注册表还指向旧路径，系统就会判断不到

为什么这会导致问题：

- 你看到的是“项目根目录里有模型，但系统没识别”
- 实际上系统在不同层里还接受别的模型路径来源
- 所以“模型只认 `models/`”这个口径并不是一开始就被强制落实的

后续是怎么修正的：

- 把模型目录统一收敛到项目根目录 [models](D:\learn\AIGC\voicescribe\0324\voicescribe\models)
- 补了旧路径 rebasing
- 在正式 spec 里把它提升为全局硬约束

### 3.2 所有引擎都要统一模型管理语义

你后来明确的口径是：

- 不能只对 FunASR 做完整模型管理
- 所有引擎都要统一模型状态、下载、删除、前端展示语义

但在你强调之前，系统实际是“半统一”状态。

之前的做法是：

1. **后端 `/engines` 有所有引擎**
   - Whisper
   - WhisperCpp
   - FunASR
   - Parakeet

2. **后端 `/models` 最初只有 FunASR**
   - 这意味着模型状态实际上只有 FunASR 有
   - 其他引擎只有模型清单，没有模型状态来源

3. **前端引擎页最初也只对 FunASR 做完整补全**
   - FunASR 会用“完整模型清单 + 状态表”合并显示
   - 其他引擎只依赖 `/models` 当前返回的数据
   - 因为 `/models` 当时没有其他引擎的状态，所以其他引擎也就不会显示未下载模型

4. **下载和删除逻辑最初也只支持 FunASR**
   - `/models/download`
   - `/models/delete`
   - 初期都只支持 FunASR

为什么这会导致问题：

- 你会看到“FunASR 看起来能管模型，其他引擎像残废状态”
- 也会看到“可选模型有，未下载模型不显示”
- 这就破坏了“统一模型管理语义”

后续是怎么修正的：

- `/models` 扩展到所有引擎
- 前端去掉只对 `funasr` 的特判
- 其他引擎也补下载和删除逻辑
- 在正式 spec 里把“所有引擎统一模型管理语义”写成硬约束
