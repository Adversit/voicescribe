# VoiceScribe 后端技术文档

更新时间：2026-03-15  
核心目录：`backend/server.py`、`backend/meeting`、`backend/diarization`、`backend/engines`

## 1. 技术栈

- Python 3.10+
- FastAPI + Uvicorn
- ASR 引擎适配层：`backend/engines/*`
- 流式会话层：`backend/meeting/*`
- 离线说话人模块：`backend/diarization/speaker.py`
- AI 后处理：`backend/postprocess/ai_refiner.py`

## 2. 主要模块

### 2.1 `server.py`

负责：
- HTTP / WebSocket 路由
- 引擎加载
- 模型管理
- speaker backend 重载
- 流式会话生命周期

### 2.2 `meeting/session.py`

负责：
- 会话编排
- `VAD -> ASR -> speaker -> summary`
- utterance 组装
- `speaker_spans` 切段重转写

### 2.3 `meeting/speaker_tracker.py`

负责：
- 流式 speaker clustering 与 mapping
- backend preload 规划
- `pyannote` 分群加载
- `CAM++` 映射加载
- `speakers`、`overlap_detected`、`speaker_spans`
- 防裂变与连续性策略

### 2.4 `diarization/speaker.py`

负责：
- 说话人注册
- 离线 diarization 结果映射
- 已注册 speaker 管理

## 3. 当前流式处理链路

```
WS /stream
  -> PCM16
  -> Silero VAD
  -> ASR
  -> pyannote clustering
  -> CAM++ mapping
  -> speaker_spans
  -> 必要时按 span 重转写
  -> utterance / summary / session_end
```

## 4. 说话人模型策略

### 4.1 流式链路

- clustering backend：优先 `pyannote/embedding`
- mapping backend：优先 CAM++（FunASR）
- fallback：必要时使用 `pyannote` 作为 mapping fallback

### 4.2 注册与离线链路

- `SpeakerDiarizer` 负责注册与离线说话人映射
- 当前默认 speaker model 为 `cam++`

### 4.3 当前阈值

- 流式 tracker `match_threshold = 0.6`
- 离线 `identify_speaker()` 默认阈值 `0.7`

## 5. 当前多 speaker 结构

`Utterance` 已支持：
- `speaker`
- `speaker_id`
- `speakers`
- `overlap_detected`
- `overlap_score`
- `speaker_spans`

这使后端不再局限于“一个 segment 只能给一个 speaker”。

## 6. VAD 内切段重转写

当前实现支持：
- 先对整段做 ASR 与 speaker 分析
- 若 `speaker_spans` 显示该 VAD 段内有多个先后 speaker 子段
- 则按 span 切出子音频
- 对每个子音频分别再调用 ASR
- 重建为多条 utterance

这一步解决的是“同一 VAD 内先后换人”的场景，不是“同时说话精确拆词”。

## 7. 防裂变策略

当前在 `speaker_tracker.py` 中已加入：
- 已注册 cluster 复用
- continuity bias
- 子窗稳定 speaker 优先
- 提高新匿名 cluster 创建门槛

目的：
- 降低单人连续说话时被裂成多个 `Speaker_N` 的概率

## 8. 模型加载与缓存

当前原则：
- 优先使用项目级 `models/`
- `pyannote` 优先查项目级 snapshot
- speaker mapping 模型优先查项目级 `models/iic` / `models/damo`
- 不再依赖运行时从用户级缓存自动迁移

## 9. speaker backend preload

`/speakers/reload-models` 当前负责：
- 依据 `enable_streaming` / `enable_diarization` 构建 preload plan
- 重载 streaming tracker
- 重置或预加载 `SpeakerDiarizer`

规则：
- `enable_streaming=true` -> preload cluster backend
- `enable_diarization=true` -> preload mapping backend

## 10. 当前后端边界

- 已支持 VAD 内多 speaker 子段拆分
- 未支持同一时间点多人同时说话的精确文本归属
- overlap 目前以启发式检测为主
- `Qwen3-ASR`、`FireRedASR2` 仍未接入推理适配
