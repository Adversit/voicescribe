## 1. 文档目的

本计划书只回答两件事：
1. VoiceScribe Windows 主窗口从初始窗口到放大窗口应该如何变化。
2. 通用页面应该如何尽量复刻原生 app，而不是继续做成网页式 dashboard。

本计划书不是像素级复刻说明，而是 UI 落地约束。后续如果代码和本计划书冲突，应以本计划书修正代码。

## 2. 当前问题重新定义

当前界面的主要问题不是 Tauri 自带，而是布局模型错误：
1. 使用了“铺满窗口的底板 + 中间居中的内容壳”结构，放大窗口后会露出大片底层背景。
2. 主窗口扩展方式像网页居中卡片，不像桌面应用的主内容区扩展。
3. 通用页面被做成了双列和多块信息板，明显偏离原生 app 的 `Form + Section` 组织方式。
4. 页面密度和窗口比例不稳定，导致看主要信息时不自然。

## 3. 新的窗口布局原则

### 3.1 单层主表面

Windows 版主窗口必须采用“单层主表面”模型：
- 整个窗口内容区只有一个主表面。
- 不允许再出现“外层背景板 + 内层主体板”的双层 panel。
- 左侧侧边栏和右侧内容区都直接落在这一个主表面上。
- 允许存在很轻的分区背景差异，但不能形成视觉上的第二层壳。

### 3.2 初始窗口到放大窗口的变化规则

参考 Typeless 的窗口行为，VoiceScribe 必须采用“固定导航 + 内容扩展”的缩放方式：
1. 初始窗口保持较紧凑的桌面设置页比例。
2. 放大窗口后，左侧侧边栏宽度基本稳定，不随窗口无限拉宽。
3. 右侧内容区随着窗口变宽、变高自然延展。
4. 不允许继续使用“中间固定宽高的壳居中显示，周围露出底板”的布局。
5. 窗口高度不能写死成一个绝对值，但也不能任意跳变。
6. 应采用有上下限的弹性窗口策略：
   - 保留统一的默认视觉高度。
   - 放大时允许在有限范围内自然增加可视空间。
   - 超出后优先让局部区域滚动，而不是让整页无限变长。

### 3.3 推荐窗口行为

推荐的实现方向：
- 初始窗口：接近原生 app 的紧凑设置窗口。
- 最小尺寸：以完整显示侧边栏和通用页主要内容为准。
- 放大策略：
  - 侧边栏固定宽度。
  - 主内容区弹性拉伸。
  - 页面内局部列表区域单独滚动。
- 不追求“整个页面随着窗口无限放大”，而追求“比例稳定、内容更舒展”。

## 4. 通用页面复刻方案

### 4.1 原生 app 的通用页基线

原生 app 的通用页来自 [SettingsView.swift](D:\learn\AIGC\voicescribe\0324\voicescribe\app\VoiceScribe\Views\SettingsView.swift)。
它的本质不是 dashboard，而是：
- `Form`
- `Section`
- 单列行式设置项
- 语言 / 输出方式 / 其他开关 / 关于信息四组内容

因此，Windows 版通用页必须尽量复刻以下特征：
1. 单列优先。
2. 分组优先于卡片。
3. 设置项采用“左侧标题和说明，右侧控件”的行式布局。
4. 不使用双列信息面板来展示版本、状态、运行信息。
5. 页面主要信息在默认窗口下尽量一次看完。

### 4.2 通用页必须包含的分组

通用页按以下顺序组织：
1. 语言
   - 默认语言
2. 输出方式
   - 输出模式
   - 如需辅助说明，放在字段下方的次级文字里
3. 其他
   - 说话人识别
   - AI 文本优化
   - 开机自启动
4. 关于
   - 版本
   - 后端连接状态

### 4.3 通用页禁止事项

通用页后续禁止继续采用以下做法：
1. 双列大网格。
2. 运行状态单独做成信息卡片。
3. 把简单设置项拆成多个大块 section panel。
4. 用大量说明文本把页面拉长。
5. 把“关于”和“运行状态”做成醒目的营销式模块。

## 5. 主窗口结构基线

### 5.1 允许保留的层级

只允许以下层级：
- Window root
- Sidebar
- Content

不允许：
- Window root
- Window shell
- Inner content panel
- Nested cards as primary structure

### 5.2 侧边栏

侧边栏保留：
- VoiceScribe 品牌名
- “设置”副标题
- 5 个导航项

侧边栏不再额外承载：
- 版本信息卡片
- 运行状态卡片
- 其他底部说明块

### 5.3 右侧内容区

右侧内容区应满足：
- 页面标题保留，但压缩高度。
- 分组间距明显小于当前实现。
- 以分隔线、轻边框、轻背景区分 section，不做厚卡片。
- 内容区应当是窗口的一部分，而不是另一个被嵌套进去的面板。

## 6. 样式方向

### 6.1 保留的方向

用户已确认保留：
- 圆角米色原生感

因此保留：
- 暖米色和浅暖白的主色层级
- 轻圆角
- 轻边框
- 很弱的阴影或完全无阴影

### 6.2 必须去掉的方向

必须去掉：
- 网页背景板感
- 大面积渐变外壳
- 过厚 panel
- 过于明显的悬浮卡片感
- 中间一块内容壳居中，放大后四周露底板

## 7. 实施顺序

1. 先修正主窗口布局模型：单层主表面 + 侧边栏固定 + 内容扩展。
2. 再重做通用页：改回单列 `Form + Section` 风格。
3. 再收其他页面密度和局部滚动策略。
4. 最后再做按钮、输入框、开关等统一细节收口。

## 8. 验收标准

调整完成后，至少满足：
1. 放大窗口后，不再看到“底层背景板 + 中间内容壳”。
2. 左侧宽度稳定，右侧内容自然扩展。
3. 通用页回到单列原生设置页逻辑。
4. 默认窗口下，通用页主要信息尽量无需整页滚动即可读完。
5. 整体视觉更接近桌面设置页，而不是网页 dashboard。
