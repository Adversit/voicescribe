## 已完成工作

### 1. 流式说话人链路调整

- 修改流式会话处理顺序，使转录先执行，再进入说话人处理阶段
- 将流式 speaker tracker 改为两阶段：
  - `pyannote` 负责分群
  - `CAM++` 负责已注册说话人的实名映射
- 保留降级路径：
  - `pyannote` 不可用时，分群回退到映射后端
  - speaker backend 整体不可用时，禁用流式说话人识别

### 2. `pyannote` 环境状态核查

- 确认实际 conda 环境名为 `voicescribe`
- 在 `voicescribe` 环境中：
  - `pyannote.audio` 可导入
  - `funasr` 可导入
  - `diart` 导入失败
- `diart` 的失败原因是与当前 `torchaudio` 版本不兼容：
  - `AttributeError: module 'torchaudio' has no attribute 'set_audio_backend'`

### 3. FunASR 本地模型优先加载修复

- 修复 `backend/engines/funasr_engine.py` 的本地路径优先解析
- 主模型、VAD、标点模型改为优先使用项目 `models/` 目录
- 这样即使本地已有缓存，也不会因为传入远程模型 ID 而再次访问 ModelScope

### 4. 引擎界面加载模型联动 speaker backend preload

- 调整 Electron 与后端接口，使“引擎界面加载模型”时可以联动 speaker backend preload
- 规则为：
  - `enableStreaming -> preload_cluster`
  - `enableDiarization -> preload_mapping`
- 该逻辑按能力规划处理，不在前端硬编码具体模型名

### 5. 项目级模型路径确认

- 已确认当前本地加载优先级是“项目级 models 目录优先”
- `pyannote` 的项目级路径为：
  - `models/huggingface/hub/models--pyannote--embedding/snapshots/...`
- `CAM++` / 其他 speaker mapping 模型的项目级路径为：
  - `models/iic/...`
  - `models/damo/...`

## 关键实现结论

### 1. 关于 `pyannote`

- 现在只要项目级 `pyannote` snapshot 存在，`speaker_tracker` 就可以直接从项目级本地 snapshot 加载
- 不再依赖用户级 HuggingFace cache
- 若项目级 snapshot 不存在，才会退回 repo id / 远程加载逻辑

### 2. 关于用户级 HF cache

- 已手动完成一次 `pyannote/embedding` 缓存迁移：
  - 项目级缓存保留
  - 用户级 `C:\Users\DingK\.cache\huggingface\hub\models--pyannote--embedding` 已删除
- 按用户要求，这个迁移与删除流程没有写入运行时代码
- 当前代码不再包含“自动从用户级 HF cache 拷贝到项目级、再删除用户级缓存”的逻辑

### 3. 关于此前判断的修正

- 此前“`HF_TOKEN` 未设置，因此不会启用 `pyannote`”这一判断已不再准确
- 当前更准确的结论是：
  - 如果项目级本地 snapshot 存在，可以直接本地加载
  - 如果项目级本地 snapshot 不存在，才会落到 repo id / 远程加载路径，并受 `HF_TOKEN` 影响
