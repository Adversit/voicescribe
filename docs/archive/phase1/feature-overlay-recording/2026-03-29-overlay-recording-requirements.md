# 2026-03-29 录音悬浮窗与录音流专题需求 更新日期：2026-03-29 适用分支：`0325main`  ## 1. 背景  当前桌面端录音悬浮窗存在四类问题： - 样式笨重，与参考胶囊浮层方向差距较大； - 快捷键首次触发后不一定稳定显示； - 悬浮窗显示后，快捷键或按钮不一定能真实停止 / 取消录音； - 中间波纹必须反映真实麦克风输入，不允许再用模拟动画冒充。 - 录音时间过短时，停止后会卡在“转录中”而不是立即收口。  ## 2. 本轮目标  1. 将悬浮窗改为“主录音流的显示层 + 显式交互入口”。 2. 首次触发时稳定显示悬浮窗。 3. 使用快捷键或悬浮窗按钮时，都能回到主窗口统一录音流。 4. 波纹只接受 Rust 录音链路发出的真实 `audio-level` 事件。 5. 录音过短时，不进入长时间 `transcribing`，而是立即关闭悬浮窗并给出明确提示。  ## 3. 硬约束  - 状态只有四种：`hidden`、`recording`、`transcribing`、`cancelled`。 - 长按模式仍需保持“按下开始，松开停止”。 - 单击模式仍为“单击开始，再按一次停止”。 - 转录中状态不再显示伪波纹。 - 取消状态仅作短暂提示，不保留笨重面板。 - overlay 页面背景必须完全透明，不能再显示米色整块底板。 - 录音态视觉必须贴近参考图：纯黑胶囊、左侧叉号、右侧对勾、中间真实波纹。 - 主窗口按钮和快捷键都必须走同一套悬浮窗显示逻辑，不能因引擎切换而出现一条链路显示、一条链路不显示。  ## 4. 验收标准  - 快捷键首次触发能稳定显示悬浮窗； - 主窗口点击开始录音也能稳定显示悬浮窗； - 悬浮窗显示后，再按快捷键能停止录音； - 点击取消 / 停止按钮能真实生效； - 波纹能明显跟随真实麦克风输入变化； - 录音时间过短时，不会卡在“正在转录”； - 结果写入 `docs/archive/phase1/第一阶段测试.md` 后，才算完成测试。
