# VoiceScribe 全系统测试方案

日期：2026-03-18

## 1. 目标与原则

本方案用于建立一套可审计、可复现、可证明正确性的系统测试体系，覆盖从 Mock 基线、真实模型短样本、长时稳定性到 Electron 端到端联调的完整验证链路。

原则：

- 先 Mock 基线，再真实短样本，最后长时全链路。
- 先验证接口契约，再验证模型结果正确性，最后验证稳定性与恢复能力。
- 通过标准必须能证明“结果正确”，而不只是“接口不报错”。
- 测试结果必须绑定复现基线、缺陷编号、日志定位与重测条件。
- 每个层级只有在满足当前口径下的验收标准后才允许写入正式状态。
- 当验收标准、关键输入数据、脚本逻辑或复现基线发生实质变化时，旧结果全部作废，必须重测。

## 2. 复现基线与环境约束

### 2.1 每轮测试必须记录的复现基线

每轮测试必须至少记录以下字段：

- Git commit/hash
- 操作系统版本与架构
- Python 版本
- Electron / Next / 前端应用版本
- GPU 型号、驱动版本、显存大小
- 实际使用的 Torch 版本、CUDA 版本、`torch.cuda.is_available()` 结果
- 后端启动入口与启动参数
- 测试脚本入口与参数
- 模型版本信息：
  - 模型名称
  - 本地路径
  - 更新时间
  - 校验值或不可变版本标识（有条件时必须补）
- 测试音频清单：
  - 文件路径
  - 裁剪偏移
  - 时长
  - 参考文本或关键词基线
  - 参考说话人信息（如适用）

### 2.2 当前默认入口

- 正式测试 Python 环境固定为 `conda` 环境 `voicescribe`
- 正式测试命令应使用：
  - 先 `conda activate voicescribe`
  - 或直接使用 `conda run -n voicescribe <command>`
- 不允许使用未激活项目环境的 base / 默认 shell Python 作为正式测试解释器
- 真实链路默认入口：`scripts/windows/dev.bat`
- 后端单独入口：`scripts/windows/start_backend.bat`
- L1 自动化入口：`scripts/windows/test_backend.bat`
- L5 自动化入口：`scripts/windows/test_real_inference.bat`
- L6 人工录音入口：`scripts/windows/test_recording.bat`
- L7 长时流式入口：`scripts/windows/test_long_stream.py`

### 2.3 当前测试音频

- 主测试文件：`artifacts/test-audio/20260313135647-信通院云大所市场部预定的会议-纯音频-1.m4a`
- 后续必须拆分出标准评测切片，并为每个切片补充：
  - 参考文本或关键词基线
  - 说话人参考信息（如适用）
  - 期望时长范围

### 2.4 模型排除规则

某模型只有同时满足以下条件时才允许记为 `SKIP`：

- 当前设备或环境明确不支持
- 排除原因已写入方案文档
- 排除日期已记录
- 重新纳入的条件已写明

如果只是“暂时没测”或“旧结果不想沿用”，不能写 `SKIP`。

## 3. 状态与门控规则

### 3.1 正式状态

只有以下 4 个正式状态：

- `PASS`：达到该层级全部验收标准
- `FAIL`：应支持但实际不满足验收标准
- `SKIP`：仅用于文档已声明的不适用项
- `BLOCKED`：被环境、上游依赖或外部前置条件阻塞，无法得出结论

### 3.2 非状态占位

测试报告中的“最新状态”允许留空。留空不是状态，只表示：

- 尚未按当前口径执行
- 或旧结果因口径升级已作废

### 3.3 门控规则

- Phase 1：`L1 + L2 + L3` 必须全部 `PASS`
- Phase 2：`L5` 必须 `PASS`
- Phase 3：`L6` 只能在 `L1-L3 + L5` 已具备有效基础时执行
- Phase 4：`L7 S1-S4` 必须全部 `PASS`，才能申请 `L7 S5`

说明：

- 模型级 `SKIP` 不自动等于层级 `PASS`
- 某层级若依赖的必测项未完成，即使其他项已通过，也不能写 `PASS`
- 已知高严重级别缺陷未闭环前，不得写 `PASS`

## 4. 缺陷闭环要求

每个已知问题必须至少记录以下字段：

- 缺陷编号
- 所属层级
- 严重级别
- 问题摘要
- 影响范围
- 当前判断：
  - 先改项目内容
  - 或先改测试脚本
- 临时规避方式
- 重测条件
- 重测结果

仅写“已知 bug”或“待确认”不满足正式台账要求。

## 5. 测试分层

### 5.1 L1 - 后端核心与 API 契约（Mock 基线）

目标：

- 验证后端 API 契约、基础错误分类与结构化日志是否稳定

执行入口：

- `scripts/windows/test_backend.bat`
- `backend/tests/test_backend_core.py`
- `backend/tests/test_backend_meeting.py`
- `backend/tests/test_backend_speaker.py`

必测范围：

- `/`
- `/health`
- `/engines`
- `/models`
- `/load`
- `/transcribe`
- `/speakers`
- `/speakers/register`
- session / speaker tracker 基础路径
- 结构化日志字段

通过标准：

- 所有必测接口返回正确 HTTP 状态与响应结构
- 错误输入返回明确错误，不允许出现未分类 500
- 结构化日志必须包含请求入口、模型/引擎、错误类别、耗时等关键字段
- 至少保留一组原始日志样本用于复核

### 5.2 L2 - WebSocket 流式协议（Mock 引擎，无需 GPU）

目标：

- 验证 `/stream` 协议契约、事件顺序、容错、并发与清理行为

执行入口：

- `backend/tests/test_streaming_protocol.py`

必测范围：

- connect / start / audio / end 生命周期
- `started` 事件结构
- `session_end` 事件结构
- `utterance` / `speaker_active` / `utterance_refined` / `summary` 事件
- invalid JSON / missing action / audio before start / double start
- concurrent sessions
- repeated sessions cleanup

通过标准：

- `start` 后必须在限定时间内返回 `started`
- `end` 后必须在限定时间内返回 `session_end`
- 二进制音频、错误输入、并发场景都不能导致无限等待或挂死
- 协议事件名、关键字段、顺序必须与文档一致
- refiner / summary 若启用，必须按预期发出事件或给出可归类错误
- repeated sessions 不得出现残留 task、异常日志或内存无限增长

### 5.3 L3 - 配置参数与音频格式边界

目标：

- 验证异常参数和异常音频输入不会导致崩溃、挂死或无提示降级

执行入口：

- `backend/tests/test_streaming_boundary.py`

必测范围：

- 配置参数边界：
  - 阈值越界
  - 负值
  - 缺省 engine
  - 类型强转
- 音频格式边界：
  - 空文件
  - 非 WAV
  - 静音 WAV
  - tiny chunk
  - odd-byte chunk
  - 多个小 chunk
  - 大 chunk

通过标准：

- 非法参数必须返回明确错误或明确且可验证的 coercion 结果
- 任意边界音频都不能导致服务挂死
- 处理结果必须在限定时间内返回错误、结束或忽略，不允许无限等待
- 相关日志必须能定位输入类型、分支与失败位置

### 5.4 L4 - 已从当前测试计划移除

- 当前不再保留独立的 L4 非流式门控层级。
- 若需验证真实 `/load + /transcribe` 的非流式质量，仅作为调试或人工抽检，不写入正式层级状态。
- 当前正式门控从 `L3` 直接进入 `L5`。

### 5.5 L5 - 真实模型流式推理 + 说话人模型矩阵

目标：

- 验证流式转写、时延、时间戳、说话人归属和模型回显是否正确

执行入口：

- `scripts/windows/test_real_inference.bat --mode stream`

必测模型：

- `funasr / paraformer-zh-streaming`
- `funasr / paraformer-zh`
- `funasr / seaco-paraformer`
- `qwen3asr / qwen3-asr-0.6b`

必测说话人模型：

- `cam++`
- `eres2netv2`
- `eres2net-large`

通过标准：

- WebSocket 建连与 `start` 成功只是最低前提
- 必须记录并评估：
  - 首条 `utterance` 时延
  - 平均与 P95 事件时延
  - `session_end` 返回时延
- `utterance` 文本必须满足文本正确性标准
- 时间戳必须单调、非零、与音频时长一致
- `speaker_model` 回显必须与请求一致
- 说话人数量与变化必须合理，不得无限新增 `speaker_N`
- 若样本具备说话人参考信息，必须验证归属一致性

### 5.6 L6 - Electron 联调 + 业务流程测试

目标：

- 验证桌面端录音链路、后端联动、业务流程、页面可见状态与用户侧可见行为

前置条件：

- `L1-L3 + L5` 全部 `PASS`

执行入口：

- `scripts/windows/dev.bat`
- `scripts/windows/test_recording.bat`

#### 5.6.3 第一轮：A-3min 主样本

触发方式：全部使用快捷键，不使用主界面按钮。

**非流式（`enableStreaming = OFF`）**

AI摘要开关在此模式下必须灰显（即 C-01 的前提条件）。转录结果写入历史记录，实时转录界面保持空状态。

| 场景 ID | 说话人识别 | AI文本优化 | 操作 | 预期输出 |
|--------|-----------|-----------|------|---------|
| S-NB-01 | OFF | OFF | 快捷键开始 → 播放 A-3min → 快捷键停止 | ① 剪贴板有纯文本，无说话人前缀；② 历史新增条目，`duration ≈ 180s`，`text` 非空，`segments` 无 `speaker` 字段；③ 实时转录界面保持空状态占位 |
| S-NB-02 | ON | OFF | 同上 | ① 剪贴板文本含说话人标签（如 `Speaker_1:` 或已注册姓名）；② 历史 `segments` 中 `speaker` 非空，且不全为同一说话人 |
| S-NB-03 | OFF | ON | 同上 | ① 剪贴板文本有可见润色（标点完整、口语词清理），与 S-NB-01 输出有差异；② 历史 `text` 为润色后版本 |
| S-NB-04 | ON | ON | 同上 | ① 历史 `segments` 含说话人标签；② 历史 `text` 为润色后版本，两者同时成立 |

**流式（`enableStreaming = ON`）**

转录结果实时显示在实时转录界面，session 结束后写入历史。

| 场景 ID | 说话人识别 | AI文本优化 | AI摘要 | 操作 | 预期输出 |
|--------|-----------|-----------|-------|------|---------|
| S-ST-01 | OFF | OFF | OFF | 快捷键开始 → 播放 A-3min → 快捷键停止 | ① 实时界面文字持续增量出现，状态显示「录音中 / 实时转录中」；② 切换到其他页再切回，文字不丢失继续更新；③ 结束后历史新增条目，`utterances` 非空，`isStreaming: true`；④ 剪贴板有对应文本 |
| S-ST-02 | ON | OFF | OFF | 同上 | ① 实时界面底部状态栏显示「[说话人名] 正在说话」，随对话切换更新；② 历史 `utterances` 每条含 `speaker` 字段，不全为同一人 |
| S-ST-03 | OFF | ON | OFF | 同上 | ① 实时界面 utterance 出现后有可见文本二次更新（refined 事件触发，原文被润色版替换） |
| S-ST-04 | OFF | OFF | ON | 同上（摘要间隔设为 120s） | ① 约 120s 时出现摘要卡片，3min 内至少出现一次，含「决议」「待办」等结构；② 历史 `summary` 非 null，含 `content`、`decisions`、`actionItems` |
| S-ST-05 | ON | ON | ON | 同上（摘要间隔 120s） | ① 说话人标签持续切换；② utterance 有 refined 更新；③ 至少出现一次摘要卡片；④ 历史含 `utterances`（有 `speaker`）+ `summary`（非 null） |

### 5.7 L7 - 长时递增压力测试
