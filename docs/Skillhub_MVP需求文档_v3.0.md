## 一、平台定位

**一句话**：AI Agent 技能的收集、组合、治理和分发平台

**核心价值**：
- 不只是"技能商店"，而是"**技能操作系统**"
- 强调**组合能力**（多技能协同）和**治理能力**（安全、质量、标准）
- 面向 ToB 和 One Person Company 场景

## 四、功能需求详解

### 4.1 Skill 数据管理

#### 4.1.1 数据导入（SkillsMP API）

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 批量导入 | MVP: 通过 SkillsMP API 按 stars 降序拉取前 5,000 个 Skill（stars >= 700）的元数据 → GitHub 下载文件，预留: 多数据源扩展 | P0 |
| 定时同步 | Cron 定时拉取（每天凌晨），以 sortBy=recent 获取最近更新的 Skill，以 SkillsMP id 去重，以 updatedAt 判断是否需要更新 | P1 |
| 手动触发 | 管理后台按钮触发导入 | P0 |
| 导入日志 | 新增/更新/跳过/失败数、错误样例、执行时间 | P0 |
| 增量更新 | 基于 SkillsMP updatedAt 只更新有变化的数据，通过 SkillsMP id 去重 | P1 |
| AI 翻译 | 导入时自动翻译 name、description、skill_md_content 为中文（Qwen-Plus），保留代码块不翻译 | P0 |

**MVP 文件存储说明**：
| 步骤 | 说明 |
|------|------|
| 下载 | 从 GitHub 下载项目 ZIP 包 |
| 解压 | 解压到服务器指定目录（storage_path） |
| 元数据 | 遍历文件树，写入 skill_files 表 |
| 统计 | 计算 file_count、storage_size |

> **⚠️ 待补充**：当前部署方案为 Vercel（Serverless，无持久文件系统），文件存储到服务器目录的方案需进一步明确（如改用对象存储 S3/OSS，或使用独立文件服务器）。

**AI 翻译步骤说明**：

| 配置项 | 值 |
|--------|-----|
| 模型 | DashScope Qwen-Plus |
| API | https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions |
| 输入 | name + description + skill_md_content |
| 输出 | 英文字段 + 中文字段（双向填充） |

**语言检测**：以 `skill_md_content` 为唯一判断依据（name 几乎全英文，不参与判断），写入 `source_lang` 字段：

| source_lang | 含义 | 翻译方向 |
|-------------|------|---------|
| `en` | 英文（绝大多数） | 原文保留英文字段，翻译写入中文字段 |
| `zh` | 中文（少数） | 原文挪入中文字段，翻译写入英文字段 |
| `other` | 非中非英（极少数） | 翻译生成英文版 + 中文版，原文不保留 |

**字段设计原则：英文字段始终存英文，中文字段始终存中文**。

翻译规则（所有方向共享）：
- **保留所有代码块（` ``` `）内容不翻译**
- **保留所有行内代码（`` ` `` ）不翻译**
- 保留 URL、文件路径不翻译
- 保留 Markdown 格式（标题、列表、表格、链接语法）
- 常见技术术语保留英文：API、SDK、MCP、Agent、Token、Prompt 等

失败处理：
| 情况 | 处理 |
|------|------|
| API 调用失败 | 重试 2 次，仍失败则对应字段留空 |
| 返回格式异常 | 记录错误，对应字段留空 |
| 字段为空的 Skill | 关键词搜索仍可命中已有字段，语义搜索暂时缺失 |
| 后续补救 | 定时任务扫描 `source_lang IS NULL` 或 `name_zh IS NULL` 的记录 |

**MVP 首批导入策略**：

| 项目 | 说明 |
|------|------|
| 筛选标准 | SkillsMP API `q=*&sortBy=stars` 前 **5,000** 个 Skill（stars >= 700） |
| stars 含义 | GitHub 仓库级别的星标数，同一仓库下所有 Skill 共享相同 stars |
| 导入方式 | 通过 SkillsMP API 按 stars 降序分页拉取（limit=100, page=1~50） |
| API 限制 | SkillsMP 搜索接口单次查询 maxResults=5000，后续扩量需联系 SkillsMP 或换用 GitHub API |

**定时更新流程**：

频率：每天凌晨执行一次（Cron）。

> **⚠️ 待确认**：Vercel Cron 免费版超时限制较短，全量更新任务可能需要外部定时触发方案，需部署侧确认。

```
┌───────────────────────────────────────────────────────────────┐
│                      定时更新流程                                │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  1. 拉取 SkillsMP 按 stars 降序的 Skill 列表                   │
│     q=*&sortBy=stars&limit=100, page=1~50（共 5000 条）        │
│     获取字段: id, name, author, stars, updatedAt              │
│                                                               │
│  2. 逐条与平台 skills 表比对（以 SkillsMP id 为匹配键）        │
│                                                               │
│         ┌──────────────┐                                      │
│         │ 平台已存在？  │                                      │
│         └──────┬───────┘                                      │
│           ┌────┴────┐                                         │
│           ↓         ↓                                         │
│         已存在    不存在 → 新增导入                              │
│           │         (下载文件、翻译、分类、生成向量、写入)       │
│           ↓                                                   │
│     ┌────────────┐                                            │
│     │ updatedAt  │                                            │
│     │ 晚于上次？ │                                            │
│     └─────┬──────┘                                            │
│      ┌────┴────┐                                              │
│      ↓         ↓                                              │
│    是 → 覆盖更新    否 → 跳过                                  │
│    (重新下载文件、覆盖存储目录、                                │
│     重新翻译、更新所有字段、重新生成向量)                        │
│                                                               │
│  3. 记录导入日志（新增数 / 更新数 / 跳过数 / 失败数）           │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

三种更新场景：

| 场景 | 说明 | 处理方式 |
|------|------|---------|
| 新增 Skill | sortBy=recent 中出现平台不存在的 Skill | 作为新 Skill 导入 |
| 内容更新 | 已在平台，SkillsMP 上 updatedAt 晚于平台记录 | 全量覆盖（文件、翻译、字段、向量） |

去重机制：以 SkillsMP 的 skill id 为唯一标识，存储在 skills 表的 `source_meta.skillsmp_id` 字段中，每次更新时通过该 id 判断是否已存在。

**后续扩量**：

降低 stars 门槛即可扩大导入范围，已有数据不受影响：

| 方式 | 预计 Skill 数 |
|:----:|:------------:|
| sortBy=stars 前 5000（MVP） | 5,000（stars >= 700） |
| 多查询合并扩量 | 5,000+（后续） |
| 联系 SkillsMP 放开上限 / GitHub API | 全量 ~160,000 |

```

**筛选逻辑**：
```
┌─────────────────────────────────────────────────────────────────┐
│  默认：精确匹配                                                  │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 选"互联网 + 技术" → 只返回同时匹配两个条件的 Skill       │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│  前端复选框：☑ 包含通用类                                       │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │ 勾选后 → 精确匹配 + 行业=通用的 + 岗位=通用的            │   │
│  └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
```

| 用户选择 | 包含通用 | 返回结果 |
|----------|----------|----------|
| 互联网 + 技术 | ❌ | 只返回 互联网+技术 |
| 互联网 + 技术 | ✅ | 互联网+技术 + 通用+技术 + 互联网+通用 + 通用+通用 |
| 不选 | - | 全部 |

**分类来源**：
| 阶段 | 方式 |
|------|------|
| MVP | LLM 分类（轻量模型，基于 name + description 判断行业/岗位） |
| MVP | 用户上传时手动选择 |
| 第二阶段 🔒 | AI 分类升级（分析 SKILL.md 完整内容，提高准确率） |

| 主题 | 支持深色/浅色切换 |
| **多语言** | **支持中/英文切换（MVP 必须）** |

**多语言支持（MVP）**：

| 内容类型 | 中英文处理方式 |
|----------|---------------|
| UI 界面 | i18n 国际化，用户可切换语言 |
| Skill 名称/描述 | 数据库存储双语字段（name / name_zh），英文字段始终英文，中文字段始终中文 |
| SKILL.md 内容 | 双语存储（skill_md_content / skill_md_content_zh），根据 source_lang 决定翻译方向 |
| 分类名称 | 双语存储（name / name_zh） |
| 原始语言标记 | source_lang 字段标识 SKILL.md 原始语言（en/zh/other） |

**语言切换逻辑**：
```
用户选择语言 → 存入 localStorage / Cookie
├── 中文：优先显示 xxx_zh 字段，无则显示原文
└── 英文：显示原文字段
```

└─────────────────────────────────────────────────────────────────────────────┘

**关键配置**：

| 配置项 | 值 | 说明 |
|--------|-----|------|
| 向量维度 | 1024 | DashScope text-embedding-v4 输出维度 |
| 存储位置 | skills.embedding | 直接存在 skills 表中，无需单独向量表 |
| 索引类型 | HNSW | 精度高、支持增量更新，适合每日新增场景 |
| 相似度算法 | `<=>` (余弦距离) | pgvector 提供的余弦相似度操作符 |
| 向量化对象 | skill_md_content_zh | 只向量化 SKILL.md 中文翻译全文（跨语言能力可同时服务中英文搜索） |
| 生成时机 | 导入/上传时 | 翻译完成后对 skill_md_content_zh 生成向量 |
| 更新时机 | 内容变更时 | skill_md_content_zh 变更则重新生成 |

**SQL 示例**：

```sql
-- 启用 pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- skills 表 embedding 字段
ALTER TABLE skills ADD COLUMN embedding vector(1024);

-- 创建 HNSW 索引
CREATE INDEX idx_skills_embedding ON skills
USING hnsw (embedding vector_cosine_ops);

-- 语义搜索查询（返回最相似的 10 个）
SELECT id, name, description,
       1 - (embedding <=> $query_vector) AS similarity
FROM skills
WHERE status = 'active'
ORDER BY embedding <=> $query_vector
LIMIT 10;
```

$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_skills_updated_at
  BEFORE UPDATE ON skills
  FOR EACH ROW
  EXECUTE FUNCTION update_updated_at();
