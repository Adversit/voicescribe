# 2026-03-15 流式说话人识别改造计划与进展

## 当前目标

当前阶段只解决一个问题：

- 一个 VAD 段内，如果是先后出现不同说话人，需要尽量稳定地识别并切开。

当前阶段明确不解决的问题：

- 不做“同一时间点两个人同时说话，各自文本精确归属”。
- 不把 `overlap` 当成主功能目标。

当前策略已经调整为：

- 默认单人。
- 只有在时间轴上出现稳定的多个 speaker spans 时，才认定一个 VAD 段是多人。
- `top1/top2` 接近只作为内部调试信号，不再直接驱动最终多人输出。

---

## 已完成内容

### 1. 流式链路改成 `ASR -> pyannote -> CAM++`

- ASR 先转录。
- `pyannote` 负责分群和匿名说话人聚类。
- `CAM++` 负责已注册说话人的实名映射。
- 引擎加载时，按能力预加载 speaker backends：
  - 开启流式时预加载 cluster backend
  - 开启说话人识别时预加载 mapping backend

### 2. 支持多 speaker labels

- `Utterance` 增加 `speakers`
- WebSocket 增加 `speakers` / `active_speakers`
- 前端、历史记录、导出已支持多 label 数据结构

说明：

- 这是结构升级，不等于已经稳定支持多人结果。

### 3. 支持 `speaker_spans`

- 一个 VAD 段内会做滑窗 speaker 判断。
- 相邻同 speaker 的窗口会合并成 `speaker_spans`。
- `speaker_spans` 现在是后续切段重转写的依据。

### 4. 按 `speaker_spans` 切段重转写

- 对一个 VAD 段先做整段 ASR 和 speaker 分析。
- 如果检测到稳定的非重叠 speaker spans，就按 span 切原始音频。
- 对每个子段分别再做一次 ASR。
- 最终重建成多条 utterances，而不是整段只给一条记录。

### 5. 项目级模型路径优先

- speaker 相关模型优先走项目级 `models/` 目录。
- `pyannote` 优先走项目级 HuggingFace snapshot。
- `CAM++` 优先走项目级 `models/iic` / `models/damo`。

## 本次修改

本次修改的核心目标是压制“裂变”：

- 明明是一个人在说话，但因为 embedding 波动，被识别成多个人。
- 当当前实名不再合适时，优先切到另一个更像的已注册说话人，而不是先退回匿名。

### 1. 最终多人判定收紧为“稳定 spans 驱动”

已修改：

- 不再因为整段 `top1/top2` 分数接近，就直接把结果标成多人或 `A / B`。
- 只有当 `speaker_spans` 中出现多个稳定说话人子段时，才保留多人结果。

当前稳定 span 的判断更保守：

- span 时长要足够长
- span 置信度要过线
- span 需要由多个滑窗共同支持

如果不满足这些条件：

- 最终结果压回单 speaker
- 不向下游传递弱证据的多人 spans

### 2. `speaker_spans` 只保留稳定 speaker

已修改：

- 滑窗仍然会继续做，用于内部判断。
- 但最终输出到 `speaker_spans` 的，是经过稳定性筛选后的 spans。
- 短暂抖动、单窗误判、弱置信度切换，不再继续往后传给切段重转写逻辑。

这一步的直接目的：

- 减少一个人被切成多个 speaker
- 减少 `MeetingSession` 按错误 spans 继续切段

### 3. 弱化 `overlap` 的用户侧影响

已修改：

- `overlap` 现在降级为内部调试信号。
- 当前阶段不再把“候选接近”直接当成最终用户可见的多人结论。
- 即使内部估计到弱 `overlap` 信号，只要没有稳定 spans 支持，最终仍按单 speaker 处理。

说明：

- 当前项目的重点不是“同时说话处理”。
- 当前项目的重点是“一个 VAD 内先后不同人说话”和“单人不裂变”。

### 4. 保留并增强后端日志，便于调试

已修改：

- 保留模型加载日志。
- 保留 speaker backend 选择日志。
- 新增流式段级日志，直接打印：
  - 当前段候选 speaker 及分数
  - 最终是否压回单人
  - 原始 spans 是什么
  - 稳定 spans 是什么
  - 为什么接受多人，或者为什么拒绝多人

当前新增日志重点在：

- `backend/meeting/speaker_tracker.py`

日志示例语义：

- `Segment 12.40-14.80 candidates: Ding:0.83, Tester:0.79`
- `Collapsing segment ... to single speaker Ding`
- `Accepting multi-speaker segment ... with stable spans: Ding:1.20s/... , Tester:1.00s/...`

目的：

- 以后再看一次日志，就能直接判断是“候选接近但证据不够”，还是“稳定 spans 已经成立”。

### 5. 优先在已注册说话人之间切换，最后才匿名

已修改：

- 整段 speaker 决策新增“注册人切换”规则。
- 如果当前 active speaker 不再最像，但另一个已注册说话人的分数已经明显领先，就直接切到那个已注册人。
- 子窗 `speaker_spans` 的决策也应用同样规则。
- 只有所有已注册说话人的证据都不够强时，才保留匿名 `Speaker_N`。

这一步解决的问题：

- 之前逻辑里，“当前实名不稳”时经常直接掉回匿名。
- 现在会先尝试：
  - 继续保持当前实名
  - 否则切到另一个更像的已注册人
  - 最后才匿名

对应代码：

- `backend/meeting/speaker_tracker.py`

对应测试：

- `test_process_segment_switches_to_decisive_registered_speaker_before_anonymous`
- `test_subsegment_switches_to_decisive_registered_speaker`

### 6. 过滤极短、空文本、噪音型匿名段

已修改：

- 在 `MeetingSession` 输出 utterance 前增加过滤。
- 对空文本、纯符号、极短匿名语气词段做直接丢弃。
- 这一步只针对低价值匿名段，不影响已注册说话人的正常短句。

这一步解决的问题：

- 压掉由于噪音、极短语气词、空白段带来的多余 `Speaker_N`
- 减少历史记录里无意义的匿名碎片

对应代码：

- `backend/meeting/session.py`

对应测试：

- `test_process_audio_segment_drops_short_anonymous_noise`

### 7. 已注册说话人切换改成“当前人 vs 更像的人”比较

已修改：

- 窗口级注册人切换不再只看泛化的 `top1/top2`。
- 现在优先比较：
  - 当前 speaker 的候选分数
  - 更像的那个已注册 speaker 的候选分数
- 只有更像的注册人相对当前人有足够领先幅度，才切换。

这一步解决的问题：

- 更符合“滑动窗口和哪个注册说话人更相似，就向哪个切换”的逻辑
- 减少因为无关 top2 候选导致的误切换

对应代码：

- `backend/meeting/speaker_tracker.py`

对应测试：

- `test_registered_switch_uses_current_speaker_candidate_as_competitor`

## 本次修改借鉴了什么项目

本次修改不是照搬某一个仓库，而是借鉴了成熟 diarization / speaker labeling 系统的共同策略。

### 1. 借鉴 `pyannote`

借鉴点：

- 先做 segmentation / diarization 时间轴，再讨论 speaker label
- `overlap` 是单独能力，不应和“段内多人”混为一谈

对当前项目的落地：

- 当前阶段不再用 `top1/top2` 接近直接代表多人
- 更强调稳定 `speaker_spans`

### 2. 借鉴 `NVIDIA NeMo`

借鉴点：

- diarization 结果依赖后处理
- 需要最小时长、平滑、重分配、连续性约束

对当前项目的落地：

- 只允许稳定 spans 进入最终多人结果
- 弱证据 span 不再直接往后游传递

### 3. 借鉴 `Google Cloud Speech-to-Text` 的 diarization 输出方式

借鉴点：

- 面向用户的输出应当是稳定的 speaker tag / time segment
- 不应把一堆不稳定候选直接展示给用户

对当前项目的落地：

- 弱候选不再直接形成最终 `A / B`
- 用户侧优先看到稳定结果

### 4. 借鉴 `Amazon Transcribe` 的 diarization 输出方式

借鉴点：

- 结果应以稳定段为单位
- 先保守输出，再逐步提升细粒度能力

对当前项目的落地：

- 当前优先保证“单人不裂变”
- 多 speaker 只在证据足够时才输出

### 5. 借鉴固定团队声纹系统的 closed-set 思路

借鉴点：

- 在固定小团队、说话人已注册的场景里，优先在已知说话人集合中做选择。
- 不把“稍微不稳”立刻解释成未知说话人。

对当前项目的落地：

- 优先保持当前已注册说话人
- 证据明显转向另一个已注册说话人时直接切过去
- 只有没有足够已注册证据时才匿名

## 当前阈值与原则

当前需要重点记住：

- 流式 tracker 的实名匹配阈值仍是 `0.6`
- 离线 `SpeakerDiarizer.identify_speaker()` 阈值仍是 `0.7`
- 本次不是简单粗暴地只调一个阈值
- 本次更重要的是把“最终多人判定”改成基于稳定 spans

当前原则：

- 候选接近，不等于多人
- 单窗抖动，不等于换人
- 没有稳定 span 支持，不展示多人结果

## 下一步

下一步继续按“先稳，再强”的顺序推进：

1. 继续观察真实录音日志，验证裂变是否明显下降。
2. 如果仍有“单人被裂成多人”，继续提高新 speaker 生效门槛，而不是先扩大多人显示。
3. 继续观察“当前实名不准时，是否能顺滑切到另一个已注册人”，避免大量匿名 `Speaker_N`。
4. 继续观察极短匿名噪音段是否明显下降，必要时再扩充过滤词和时长规则。
5. 只在当前阶段稳定后，再考虑更完整的时间轴 diarization 优化。
6. 未来如果要做真正的“同时说话文本精确归属”，再单独开新阶段，不和当前阶段混做。
