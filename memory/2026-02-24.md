# 2026-02-24 工作记录

## 流式传输重构（前后端）

### 1. 通用设置新增开关
- 新增设置项：`enableStreaming`（启用流式传输）
- 默认值：`false`
- 相关文件：
  - `frontend/electron/store.ts`
  - `frontend/electron/preload.ts`
  - `frontend/src/components/settings/GeneralSettings.tsx`

### 2. 前端录音链路调整
- 录音开始时：
  - 若 `enableStreaming=true`，建立 WebSocket 会话并实时发送 PCM 分片
  - 若 `enableStreaming=false`，沿用原“录音结束后整段上传”路径
- 流式 `start` 传参包含：
  - `engine` / `model` / `language` / `hotwords` / `enable_ai_refine`
- 相关文件：
  - `frontend/src/components/GlobalRecordingManager.tsx`
  - `frontend/src/lib/stream-transcriber.ts`
  - `frontend/src/lib/wav-recorder.ts`
  - `frontend/src/lib/audio-recorder.ts`

### 3. 后端 /stream 重构
- 接口：`backend/server.py` 中 `@app.websocket("/stream")`
- 分块策略已按需求改为：
  - `chunk_duration = 30` 秒
  - `sample_rate = 16000`
  - 16-bit PCM（2 bytes/sample）
  - `chunk_size = 30 * 16000 * 2`
- 增加边界重叠：
  - `overlap_duration = 3` 秒（仅用于 partial 分块）
  - 目的：减轻 chunk 边界断词
- 处理流程：
  - 收到音频字节流 -> 累积到 `chunk_buffer` 和 `full_pcm`
  - 满足 `chunk_size` -> 转写该块并返回 `partial`
  - 收到 `end` -> 对整段 `full_pcm` 转写并返回 `final`

### 4. AI 文本优化触发时机修正
- 统一规则：
  - 不在 partial 阶段执行 AI 优化
  - 仅在本次录音结束（`end` -> `final`）后执行一次
- 复用现有 `AIRefiner` 逻辑，无新增独立优化链路
- 通过 `enable_ai_refine` 控制本次会话是否执行

### 5. 词汇（热词）链路检查结果
- 词汇界面增删改会保存到 `settings.vocabulary`
- 普通转写与流式转写都会携带热词
- 后端在 FunASR 路径下会实际使用热词
- 结论：词汇链路通

### 6. 其他稳定性改动（同日）
- 流式 final 等待超时提升到 10 分钟
- WebSocket 异常关闭可及时失败，避免无意义等待
- 修复 `/stream` 中 `DEFAULT_MODELS` 未定义问题
