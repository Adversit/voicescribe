## 2. Typeless 功能调研结论（截至 2026-03-02）

基于官网与帮助中心公开信息，Typeless 的定位已不只是“语音转文字”，而是“语音驱动的文本编辑与问答助手”。核心能力可归纳为：

1. 基础输入：
- 语音转写（Speak to write）。

2. 文本编辑类：
- 对选中文本执行语音编辑（Speak to edit selected text）。
- 预设命令体系（如改写、总结、润色等）。
- 支持自定义命令和自定义提示词（Custom command / prompt）。

3. 问答与检索类：
- 基于选中文本提问（Ask anything）。
- 可做“快速答案”，结合网页搜索与总结（Quick answers, internet-assisted）。

4. 语言类：
- 翻译模式（支持多语输入/目标语言输出）。

5. 使用形态：
- 支持“Talk mode”工作流（语音驱动编辑/命令执行）。
- “Works anywhere”的跨应用输入定位（办公写作流场景）。

6. 版本信号（公开 release notes）：
- macOS: v0.9.0（2025-12-24）
- iOS: v0.2.0（2025-12-31）提到“Speak to Edit”
- Windows: 公开到 v0.1.0（2025-10-22，Beta）
- Android: 公开到 v0.2.0（2025-12-03）

备注：以上为公开页面可检索信息；个别功能细节可能随版本变更。

## 3. 当前系统已实现能力（VoiceScribe）

当前项目已实现的是“本地语音转写工具 + 模型管理 + 说话人能力 + 历史管理”，并已具备工程化基础。

1. 录音与转写主链路
- 全局快捷键触发录音（Electron `globalShortcut`）。
- 托盘驻留 + 悬浮录音状态窗（含音量波形、thinking 状态）。
- 音频编码为 WAV PCM16/16kHz/单声道，上送后端转写。
- 非流式与流式（WebSocket `/stream`）两条路径并存，流式支持 partial/final。

2. 后端引擎与模型管理
- 引擎：`whisper` / `whispercpp` / `funasr` / `parakeet`（按环境可用性）。
- 模型能力：列出、下载、删除、加载。
- mock 模式可跑通联调。

3. 说话人相关
- 说话人注册、列表、删除。
- 支持说话人分离/映射（FunASR + embedding 映射逻辑）。

4. 文本后处理
- 热词词表（前端维护、后端传参）。
- AI refine 开关（后端后处理，当前实现主要围绕热词纠正触发）。

5. 输出与历史
- 输出模式：`clipboard` / `directInput` / `both`。
- 历史：搜索、编辑、删除、清空、导出（TXT/MD）。
- 设置持久化（Electron settings + Zustand persist）。

## 4. 差距分析（对照 Typeless）

下面按 Typeless 核心能力逐项对照：

1. 语音转写
- 现状：已实现。
- 结论：这块是当前系统强项。

2. 对选中文本语音编辑（Speak to edit selected text）
- 现状：未实现。
- 差距点：当前仅有“整段转写后输出”，没有“读取当前选中文本 -> 按命令编辑 -> 回写”的闭环。

3. 基于选中文本提问（Ask anything）
- 现状：未实现。
- 差距点：当前无“选中文本上下文问答”接口与 UI。

4. 语音命令系统（预设命令 + 自定义命令）
- 现状：未实现（仅有热词与有限 AI refine，不是命令路由系统）。
- 差距点：缺少命令解析、命令注册、命令执行器。

5. 翻译模式
- 现状：未实现。
- 差距点：当前 `language` 更偏向 ASR 识别语言，不是“输入语言 -> 输出目标语言”的翻译工作流。

6. 快速答案/联网检索增强
- 现状：未实现。
- 差距点：当前没有 Web 检索+总结的通路。

7. 实时体验（产品层）
- 现状：后端有 `partial`，但前端目前主要打印日志，未形成可见的实时增量编辑体验。
- 差距点：离 Typeless 的“Talk mode 编辑反馈”还有产品层差距。

8. 跨应用输入稳定性
- 现状：`directInput` 依赖 `robotjs` 或 PowerShell SendKeys，失败时回退为“只复制剪贴板”。
- 差距点：稳定性和“所见即所得”的一致性仍不足。

9. 个性化（长期风格/命令记忆）
- 现状：有手动词表；无长期写作风格学习、无命令偏好学习。
- 差距点：缺少用户级个性化层。

10. 工程质量项
- 现状：项目已有脚本测试与文档，但仍明确存在 E2E smoke test 待补项。
- 差距点：端到端回归与功能验收自动化不足。

## 5. 还需要做什么（建议优先级）

## P0（先做，2-4 周）

1. 建立“工作模式”而不只是“转写模式”
- 新增模式：`dictate` / `edit_selected` / `ask_selected` / `translate`。
- 设置项与状态机先打通，功能可先做最小版。

2. 把流式 partial 变成用户可见能力
- 现在已有 `/stream` partial，前端需真正显示并可选择“最终覆盖/增量追加”策略。

3. 补齐翻译最小闭环
- 新增翻译目标语言设置和后端翻译接口（可先用单一 provider）。

4. 强化 directInput 成功率与回退提示
- 明确成功/失败反馈，不要“静默失败 + 用户手动猜测”。

## P1（第二阶段，4-8 周）

1. 选中文本编辑闭环（核心）
- 获取当前选区文本 -> 命令/提示词执行 -> 回写替换。

2. 命令系统
- 预设命令库 + 用户自定义命令（模板化 prompt + 参数）。

3. Ask anything（最小版）
- 先做“仅基于选中文本上下文问答”，再扩展联网检索。

## P2（第三阶段）

1. 个性化层
- 用户词典自动增长、风格偏好、常用命令快捷入口。

2. 隐私与数据治理设置
- 历史保留时长、自动清理、导出与彻底删除。

3. 补齐 E2E 回归
- 至少覆盖：录音 -> 转写 -> 输出 -> 历史 -> 导出。

## 6. 怎么做（技术实施建议）

1. 后端新增统一任务接口
- 建议新增 `/process`（或分开 `/rewrite` `/ask` `/translate`），输入统一结构：
  - `mode`
  - `dictation_text`
  - `selected_text`
  - `command_id`
  - `target_language`
  - `context`
- 输出统一结构：`result_text` + `trace` + `latency_ms`。

2. 建立“命令路由器”
- 新模块：`backend/postprocess/command_router.py`
- 负责把用户命令映射到具体执行器（rewrite/translate/ask/search）。

3. 前端新增模式与会话层
- Electron store 增加：
  - `mode`
  - `targetLanguage`
  - `commandPreset`
  - `customCommands[]`
- UI 在 General/新增 Command 页配置。

4. 选中文本能力接入
- 主进程增加 `get-selected-text` 与 `replace-selected-text` 能力。
- 按平台做可插拔实现（Windows/macOS 各自通道），失败时显式回退。

5. 实时体验升级
- `GlobalRecordingManager` 将 partial 结果上屏，不只 `console.log`。
- 增加“partial 标记 + final 合并策略”。

6. 测试与验收
- Playwright/Electron E2E：最少 5 条主路径。
- 后端接口测试：新增 `mode` 相关用例。

## 7. 结论

当前 VoiceScribe 已完成“高质量本地转写器”的主体能力，但与 Typeless 的差距主要不在 ASR，而在“语音驱动编辑/问答/命令系统”这一层。  
要对齐 Typeless，关键不是再加一个引擎，而是升级产品抽象：从“转写工具”升级为“语音文本操作系统（Mode + Command + Context）”。

## 11. 2026-03-03 Bug修复补充（流式转写 + 模型缓存 + AI修正）

### 11.1 FunASR 主模型重复下载（hub/models 与 models 双目录）
- 现象：模型管理已下载到 `~/.cache/modelscope/hub/models/...`，但加载时仍再次下载到 `~/.cache/modelscope/models/...`。
- 根因：`/models/download` 与 `FunASR AutoModel(model=model_id)` 使用的缓存路径不一致。
- 修复：
  - `backend/engines/funasr_engine.py` 的 `load(...)` 增加 `local_model_path` 参数，优先本地目录加载。
  - `backend/server.py` 的 FunASR `/load` 与预加载逻辑优先读取 registry 路径并传入 `local_model_path`。
- 结果：日志出现 `Using local model path: ...hub/models/...`，不再触发主模型二次下载。

### 11.2 FunASR 依赖模型（VAD/PUNC）重复下载到 models
- 现象：主模型已走 hub，本次又下载 `speech_fsmn_vad...` 与 `punc_ct-transformer...` 到 `~/.cache/modelscope/models/...`。
- 根因：FunASR 内部依赖模型仍按模型 ID 走默认缓存。
- 修复：
  - `backend/engines/funasr_engine.py` 的 `load(...)` 增加 `local_vad_path`、`local_punc_path`。
  - `backend/server.py` 新增依赖模型预取与本地路径传递，优先使用 `hub/models` 本地目录。
- 结果：日志出现：
  - `Using local VAD path: ...hub/models/...`
  - `Using local PUNC path: ...hub/models/...`
  并且不再出现下载到 `~/.cache/modelscope/models/...`。

### 11.3 已清理重复缓存目录（保留 hub）
- 删除：
  - `~/.cache/modelscope/models/iic/speech_seaco_paraformer_large_asr_nat-zh-cn-16k-common-vocab8404-pytorch`
  - `~/.cache/modelscope/models/iic/speech_fsmn_vad_zh-cn-16k-common-pytorch`
  - `~/.cache/modelscope/models/iic/punc_ct-transformer_cn-en-common-vocab471067-large`
- 保留：对应的 `~/.cache/modelscope/hub/models/...` 目录。

### 11.4 AIRefiner 热词替换超时
- 需求：先不改热词数量策略，仅提高超时。
- 修复：`backend/postprocess/ai_refiner.py`
  - `refine(..., timeout=1200)`
  - `_replace_hotwords(..., timeout=1200)`
- 结果：默认超时从 30s 提升到 20 分钟（1200s）。

### 11.5 Windows 下 Claude 子进程输出解码异常
- 现象：
  - `UnicodeDecodeError: 'gbk' codec can't decode byte ...`
  - 随后 `NoneType has no attribute strip`
- 根因：`subprocess.run(text=True)` 走系统默认 GBK 解码，且 stdout 异常后未做空值保护。
- 修复：`backend/postprocess/ai_refiner.py`
  - `subprocess.run(..., encoding='utf-8', errors='replace')`
  - `output = (result.stdout or '').strip()` 后再判空处理。
- 结果：上述两类异常不再出现。

### 11.6 流式输出节奏（当前实现）
- 当前 WebSocket `/stream`：
  - `partial` 按 30s 音频分片触发。
  - 分片重叠 3s（连续录音通常约每 27s 产生一条新 partial）。
  - `final` 在收到 `action=end` 后输出。

### 11.7 Claude Haiku 实测延迟（本机）
- 连续实测 `claude --model haiku --print`：
  - 短 prompt：约 26s
  - 长 prompt（热词替换场景）：约 75s
  - 最小请求三次：约 32s / 22s / 21s
- 结论：当前环境下 Haiku 并非秒回；存在 CLI 启动 + 网络 + 服务端处理开销。
